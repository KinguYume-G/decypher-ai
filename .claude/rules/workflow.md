# Workflow Rules — Claude Code 开发流程约定

> 这是行为规则文件。Claude Code 在执行任务时必须遵守以下流程。

---

## Git 提交规范

每完成一个功能点必须提醒我 commit，格式如下：

```
feat: 添加用户注册接口
fix: 修复 task 状态更新不同步的问题
docs: 更新 API 文档
refactor: 重构 AI 分析 pipeline
test: 添加用户认证单元测试
chore: 更新依赖版本
```

**规则：**
- 每完成一个完整功能模块（不是一个文件）才 commit 一次
- commit 信息用中文，动词开头
- 不要把未完成的功能放进 commit

---

## 开发顺序规则

每个功能模块必须按以下顺序开发，不得跳过：

1. **Model**（数据库模型）
2. **Schema**（Pydantic 请求/响应结构）
3. **Service**（业务逻辑）
4. **API Route**（路由，只调用 service）
5. **Test**（至少写 happy path 测试）
6. **确认我测试通过后**才进入下一个模块

---

## 任务拆解规则

- 每次只做**一个模块**，不要同时改多个文件
- 生成代码前先输出「我打算做什么」，等我确认
- 超过 50 行的文件生成完后，提示我 review 关键逻辑
- 发现有歧义的需求时，先问我，不要自己猜

---

## 文件修改规则

- 不要删除已有的注释
- 不要修改 `CLAUDE.md`、`docs/` 下的文档（除非我明确要求）
- 不要修改 `docker-compose.yml` 的端口映射
- 新建文件前先确认目录结构是否正确

---

## 报错处理规则

遇到报错时：
1. 先复述报错信息（不要猜）
2. 分析最可能的原因（1-3个）
3. 给出修复方案，等我确认再执行
4. 不要同时修改多个地方来"试试看"

---

## 每次对话开始时

如果我没有手动 `@CLAUDE.md`，你可以提醒我：
> "建议先 @CLAUDE.md 让我了解当前项目状态"
